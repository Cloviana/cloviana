### Success Criteria for Platform Evaluation

- **Volume Processing Capacity**

  - Full client portfolio: 5-6 million transactions/month
- **Platform Usability**
  - Minimal team involvement for configuration setup
  - Intuitive interface for non-technical users
- **Output Flexibility**
  - Need customizable formats for client reconciliation
  - Must enable payment application/reversal workflows
  - Currently very ad-hoc per merchant requirements

### File Structure & Reconciliation Logic

- **ERP File (Primary)**
  - Key fields: Date, account number, amount
  - Secondary matching: Reference number in notes field
  - Contains client payment references (cupón numbers)
- **Gateway Files (Secondary)**
  - Two separate files by city (Chihuahua, Torreón)
  - Fixed-width TXT format
  - Account numbers start with “10”, cupón references start with “0”
  - Known issue: Duplicate transactions across different dates requiring cleanup
- **Reconciliation Rules**
  1. Primary match: Account number + date + amount
  2. Secondary match: Reference number + date + amount (for unmatched items)

### Output Options Available

- **Four delivery methods offered:**
  1. Slack/email notifications (daily alerts)
  2. Automated + customizable reports
  3. API integration to client databases (BigQuery, etc.)
  4. Automated accounting entries (manual work elimination)
- **Configuration flexibility**
  - Non-technical user setup
  - Custom formatting for client requirements
