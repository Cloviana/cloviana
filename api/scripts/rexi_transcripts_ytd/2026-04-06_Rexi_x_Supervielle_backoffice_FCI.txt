### FCI Back Office — Conciliation Process (Alejandro Vitale)

- Fund: Premier Renta CP (pesos) — money market, highest transaction volume
- Inputs (downloaded daily from BanTotal):
  1. Current account (suscripciones received)
  2. Internal account (rescate payments)
  3. Third account (additional operatoria)
- Fourth input: suscripciones + rescates report from Visual Fondos (portfolio admin system)
- \~1,500 movements/day (previously up to 20,000 when Inversión Rápida was active)
- Current process: provisional Excel macro groups by client name, sums amounts, crosses against Visual Fondos
  - Grouping by name because BanTotal extract has no unique transaction ID
  - Ideal: match at transaction level, not grouped by name
- Key reconciliation challenge: MEP transfer credits arrive with no client name (clients without a monetary account at the bank)
  - Possible workaround: match by date + amount, flag ambiguous cases as pending for manual review
- Known data quality issue: typos in client names cause false differences (e.g., missing ñ)
- Cancellations/reversals: appear as a debit in the same file → net to zero → should not cross against Visual Fondos
- Output when differences exist: adjustment file (prelote) imported into BanTotal to execute mass corrections
  - Used for recovery (overpayment) or adjustment (underpayment)
  - Occurs \~2–3 times per year, not daily
- Time cost: 5–10 min to run the macro + \~30 min to analyse differences = \~1 hour/day in normal conditions
  - On exception days (e.g., reversal date mismatch across two days), can consume the entire day
  - No contingency mechanism currently exists at the systems level

### Custodia y Control Contable — Corresponsales (Matías Pedraza)

- 16 correspondent accounts held abroad
- Inputs:
  - 13 accounts via Magnafile (bank system) → downloaded manually as PDF
  - 3 accounts arrive by email (BOFA, Citi, and one other) — not in Magnafile
- Contra input: BanTotal accounting ledger (mayor contable), downloaded via file transfer query
- Current conversion process:
  1. Copy PDF content into a TXT file (manual, one TXT per correspondent)
  2. Excel macro converts TXT → structured Excel format
  3. Access macro runs reconciliation per correspondent, using multiple equivalence tables to match references
- Core problem: accounting references in BanTotal rarely match the references in the correspondent extract
  - Person who built the macro added many cross-reference tables over time; still incomplete
  - Some concepts in the extract were never parameterised → movements fall out of the macro
  - Some items only matchable by amount + date, with no reference link → macro can’t auto-match
- Output: daily reconciliation report sent by email to relevant internal sectors (comercio exterior, cambios, títulos/mercado)
  - Sectors receive “partidas pendientes” and investigate/resolve on their side
  - Rexi/back office team does not investigate differences — that responsibility sits with each sector
- Format: standard banking reconciliation layout (opening balance, movements, closing balance, pending items at debit/haber) — format is audited externally, cannot easily be changed
- Historical log of all auto-matched items stored in Access — used as reference for lookups
- Time cost: \~1.5 to 2 hours/day (macro processing time + email handling from sectors)
  - Does not include time spent by receiving sectors to investigate and resolve their differences
- Volume: high on large correspondents; some have very few movements, others concentrate most activity
