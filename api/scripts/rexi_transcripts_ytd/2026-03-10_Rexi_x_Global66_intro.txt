### Global66 Operations Overview

- 150 bank and partner accounts across multiple countries
  - Multiple currencies and formats per account
  - Different operational models: batch processing, API integration, manual downloads
  - Ecuador example: manual letter downloads only
- Daily transaction volume: 40,000+ transactions requiring reconciliation
  - Prepaid card operations across 3 countries
  - Mix of remittances, crypto/stablecoins, traditional banking
- Team structure: 9-person reconciliation team
  - Mature processes developed over past year
  - Own technology infrastructure and development team
  - In active automation phase

### Current Reconciliation Challenges

- Process complexity from partner diversity
  - Each bank/partner has unique formats and timing
  - Manual cartola downloads still required for many accounts
  - Integration gaps with existing solutions
- Daily reconciliation workflow
  - End-of-day cash position reports per account
  - Balance comparison: bank statements vs internal ledger
  - Any discrepancies flagged as “quiebres” (breaks)
- Previous vendor evaluation
  - Conciliar: solves \~70% of problem but expensive at scale
  - Volume-based pricing becomes cost-prohibitive
  - Still requires significant manual intervention

### Rexi Product Demonstration

- Four-stage reconciliation orchestration
  1. Automated data ingestion via APIs/SFTP
  2. Data transformation and normalization with AI
  3. Reconciliation processing with configurable matching rules
  4. AI-powered discrepancy investigation and resolution
- Key differentiators from competitors
  - AI-native platform vs retrofitted solutions
  - Self-serve configuration vs consulting-heavy implementation
  - Usage-based pricing vs transaction volume pricing
- Problem-solving capabilities
  - Clustering transactions by root cause
  - Automated solution suggestions with confidence scoring
  - Learning system that improves matching over time

### Strategic Context

- Global66 current approach: in-house development with own tech team
- Open to exploring external solutions after internal process standardization
- Cost sensitivity around volume-based pricing models
- Need for 100% automation given transaction scale and complexity
