### Banco Galicia Context

- Augusto Salvador Basile leads all product delivery and development — product tribes, software development, client-facing and internal systems
- Erico Ignacio Behmer had introduced the meeting; Symmetric already implemented in the accounting team for reconciliations
- Galicia’s current reconciliation setup is fairly resolved — results ready by 7am daily, built with bots and internal tooling over time
- No resolution workflow for unmatched items — system surfaces differences, but the resolution process is manual from there

### Key Pain Points Identified

- “Contabilidad entre casas” flagged as a major, chronic problem
  - Bank’s accounting = sum of each branch’s individual accounting (legacy of fully asynchronous, branch-based model)
  - Clients can now transact at any branch, but accounting entries still need to map to the home branch → constant accounting imbalances
- Augusto’s “lightbulb moment”: processes they’re *not* reconciling today, where they don’t know if they’re losing money
  - Payments to card networks (e.g. Prisma) — unclear if controls are by reasonableness or active transaction-level verification
  - Low visibility, little active control over these flows
- Existing reconciliation won’t be replaced — preference is to attack unresolved, manual, Excel-based processes first

### Deployment & Commercial Considerations

- Augusto raised cost concern directly: if the model is “complement, not replace,” Rexi’s cost stacks on top of existing Symmetric fees
  - Agreed framing: long-term north star is replacing Symmetric, but short-term entry point is unresolved flows
- Three deployment modalities discussed: cloud SaaS (preferred), embedded solution, customer-deployed
  - Hosted on AWS US-East-2; multi-region capable
  - Galicia likely to raise data residency and security requirements — agreed to start with dummy data to sidestep this initially
- Recommended approach: start with dummy data demo scoped to a specific use case, then engage security/infra teams separately

### Potential Use Cases to Explore

- Medios de pago (highest pain): card flows, chargebacks, presentaciones vs. transaccionado (can lag up to 90 days)
- Seguros (insurance): typically a painful reconciliation process
- Tax reconciliation (conciliación impositiva): validated pain point with other banks
- Horizontal across all products: accounting control per product line — the “contabilidad entre casas” problem
- Revenue leakage: contract-vs-actual fee/revenue validation with external providers
