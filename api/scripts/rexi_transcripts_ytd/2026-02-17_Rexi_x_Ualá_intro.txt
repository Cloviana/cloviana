### Ualá Mexico’s Current Reconciliation Setup

- Mexico never implemented Simetrik (unlike Argentina/Colombia)
  - Lacked the know-how when other countries had it
  - Team decided to build internal solution instead
- Built entire reconciliation process in SQL on BigQuery
  - All controls now mounted in BigQuery with automated execution via Cronos
  - Daily dashboards show total transactionality, OK statuses, and deviations
  - Downloadable detail of deviations available
- Operations team built and maintains everything internally
  - Promotes knowledge acquisition across team members
  - No dependency on external engineering support
- Colombia and Argentina still using Simetrik while migrating to similar BigQuery model

### Risk Assessment and Process Flow

- Main risk identified: data integrity issues
  - If BigQuery tables have inconsistencies, control outputs get affected
  - Easy to detect when tables aren’t updated (all transactions show as deviations)
- Multiple parties in transaction flow create complexity:
  1. Despachador (dispatcher)
  2. Core bancario (banking core)
  3. Galileo (card processor)
- Investigation process when deviations occur:
  - First check in BigQuery
  - If insufficient, access individual systems directly
  - Escalate to middle office team if needed
  - Can download Banxico dataset as final step
- Deviation rates are excellent: less than 1% deviation in SPEI (main product)
  - Spikes only occur during incidents, always tied to specific technical issues

### Operational Performance and Scalability

- Two and half years of intensive work to reach current state
  - Initial year required working weekends consistently
  - Now stabilized with minimal daily maintenance
- Process scales well with volume
  - Queries don’t change based on transaction volume
  - New products follow same control structure logic
- Team knowledge well-distributed to reduce single points of failure
  - Automated processes reduce dependency on individual execution
  - Documentation and cross-training implemented
