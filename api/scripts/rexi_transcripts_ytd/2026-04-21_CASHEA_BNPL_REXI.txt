### Current Bank Reconciliation Process at Cashea BNPL

- **Key Personnel:**

  - Daniela Avendaño - Treasury Manager
  - Juan Reyes - Lead de Contabilidad
  - Jerónimo Álvarez - Odoo Development
  - John Erazo - BNPL Accounting Team

- **Current Situation:**

  - ERP: Odoo
  - 2.8M transactions monthly
  - 64 bank accounts across 12 banks
  - Only 8% automated uploads, rest manual

- **Two Current Reconciliation Methods:**

  1. Odoo Tablero Module: 20 minutes per transaction
  2. Manual via Google Sheets/Excel
    - Load into ERP
    - Manual status changes in general ledger
    - No proper traceability

### Existing Technical Process

- **Manual Extract Loading:**

  - Analyst downloads bank statements manually
  - Uploads to ERP
  - ERP creates automatic registry

- **Transitional Account System:**

  - All transactions initially go to “Transitoria General”
  - Treasury team analyzes transitional account
  - Analyst performs reclassification
  - Goal: transitional accounts should always balance to zero
  - Transitional account serves as bridge between bank and accounting

- **Reclassification Logic:**

  - Analyst reviews bank statement to understand transaction nature
  - Assigns correct account (expense, asset, liability)
  - Example: Bank commission → expense account
  - Example: Loan payment → liability account reduction

### Desired Automated Solution

- **Automatic Extract Loading:**

  - Bank statements flow to Odoo without manual intervention
  - Eliminates errors and compliance issues
  - Direct bank connections needed

- **Parametrized Reclassification:**

  - Rules based on bank codes, amounts, dates
  - High-volume transactions automated (e.g., bank commissions)
  - Exception handling via templates for complex transactions
  - Some banks combine interest + principal in single payment

- **Automatic Reconciliation Engine:**

  - Matches transitional general against balance/result accounts
  - Uses amount, date, and bank reference
  - Final compliance check
  - Handles unmatched items for manual review

### Venezuelan Banking Challenges (Sebastian Monti - Core Payments)

- **Operational Issues:**

  - Banks change contracts without notice
  - Format changes in extracts without warning
  - System intermittencies and incomplete data
  - Data loss detection difficult (gradual vs. complete failures)

- **Partnership Requirements:**

  - Need partner to own SLA and risk
  - Commercial/political leverage with banks
  - Support for bank negotiations
  - Ranking system for bank performance and stability

### Technical Integration Requirements

- **Odoo Integration:**

  - API connections for data ingestion
  - Dictionary mapping for account classifications
  - Automated posting of reconciled transactions
  - Support for new financial operations as they emerge

- **Multiple Transitional Accounts:**

  - General transitional (mirrors bank statements)
  - Collections transitional
  - Payments transitional
  - Double reconciliation process required

- **Payment Processing:**

  - Current: Manual one-by-one payment entry
  - Desired: Automated TXT file generation for bank batch processing
  - Integration from ERP to bank systems

### Implementation Considerations

- **Historical Data:**

  - Can process retrospective reconciliations
  - Option to start clean or include historical backlog

- **Collaboration Requirements:**

  - Multiple squads involved (accounting, financial, treasury)
  - Changes must not impact historical accounting
  - Alignment needed across all departments

- **Integration with Wallet Project:**

  - Andrés leading wallet integration
  - BNC and Mercantil integrations in progress
  - Accounting model and chart of accounts being finalized
