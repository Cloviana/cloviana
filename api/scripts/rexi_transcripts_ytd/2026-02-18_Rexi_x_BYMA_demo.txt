### BYMA Current Reconciliation Process & Pain Points

- Manual balance-level reconciliation vs transactional matching needed
- Volume: \~30,000 transactions daily (78k lines including debit/credit entries)
- Payouts have unique IDs, pay-ins don’t - complicates matching
- One-to-many transaction groupings require manual investigation
- Mid-ERP transformation to SAP HANA - opportunity for clean process implementation

### Rexi Platform Demo & Capabilities

- Automated data ingestion from multiple sources (4+ banks)
  - Standardizes different formats automatically
  - Handles date/amount variations across providers
- Reconciliation engine features:
  - One-to-one, one-to-many, many-to-many matching strategies
  - Tolerance settings for dates (days/hours/minutes) and amounts (percentage/absolute)
  - Multi-pass matching: first by ID, then by bank number + date + amount + direction
- Post-reconciliation validation:
  - Status verification (approved/processed)
  - Fee checking and settlement timing analysis
  - Critical field comparison with normalization
- Automated outputs:
  - Exception management for known one-sided transactions
  - Daily email/Slack alerts with configurable thresholds
  - Custom dashboards and reporting
  - Optional accounting entry generation with approval workflows

  - Balance validation controls (daily sum-to-zero checks)
