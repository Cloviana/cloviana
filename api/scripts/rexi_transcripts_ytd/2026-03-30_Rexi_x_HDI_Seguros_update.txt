### SAP Migration Update

-   SAP implementation postponed due to budget constraints and consultant review issues
-   Would have delayed Rexi integration by 2 years (1 year SAP implementation + delays)
-   HDI decided to proceed with Rexi before SAP to avoid extended timeline

### Alternative Implementation Path

-   Simplified process available if Rexi doesn’t access HDI systems directly
-   HDI can export database files for Rexi to ingest
-   Requires additional security checks but bypasses 3-month IT approval process
-   Only needs NDA signing vs full project management approval
-   Avoids risk of IT rejection after lengthy approval process

### PDF Processing Use Case

-   HDI receives PDFs from 15+ insurance intermediaries with payment information
-   Each intermediary uses different PDF formats but same 5 data fields:
    -   Name
    -   ID number
    -   Payment amount
    -   Payment date
    -   Other standard fields
-   Currently manual process: download PDF → extract data → input to Excel
-   Identified as most painful manual process that can be handled outside main systems

### Technical Requirements Discussion

-   Rexi currently processes TXT, CSV, SFTP, direct integrations
-   PDF reading capability not yet built but should be straightforward to implement
-   Proposed automated ingestion via data lake or bucket system
-   Rexi’s platform is fully agentic with specialized agents for each process step
-   Agents learn from user actions (approvals, rejections, manual matches)

### Additional AI Initiatives at HDI

-   Exploring Teams-integrated agent for operational support queries
-   Previous Copilot implementation failed
-   Considering AI agent for collections/payment reminders with phone calls
-   Rexi platform allows conversational queries on conciliation data
-   Teams integration not currently available but web application access possible

### Next Steps

3.  HDI shares sample PDF files after NDA execution
4.  Rexi evaluates PDF processing development requirements
