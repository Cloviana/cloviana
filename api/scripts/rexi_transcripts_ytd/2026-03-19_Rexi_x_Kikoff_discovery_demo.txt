- Strong engineering team but reconciliation not priority for internal build
- Main pain points:
  - Multiple changing data sources as company scales
  - Heavy operational burden from manual processes
  - Edge cases beyond initial payment-to-invoice matching
- 95% of transactions are straightforward one-to-one matches
- Remaining 5% involve complex scenarios:
  - Chargebacks appearing months after original transaction already reconciled
  - Refunds, refund reversals, representments
  - Multiple Tabapay transactions matching single invoice

### Platform Demo Key Features

- Automated data ingestion from any source (APIs, SFTPs, databases)
- Data standardization without modifying original data
- Flexible reconciliation rules:
  - One-to-one, one-to-many, many-to-one, many-to-many matching
  - Multiple sweeps with different tolerance thresholds
  - Dependent reconciliations for complex scenarios
- AI agents analyze unmatched transactions, suggest improvements
  - Trained on wider set of edge cases across customer base
  - Propose new matching rules, patterns, tolerance adjustments
- Export capabilities to various formats, automated reports to databases
- Multi-entity support with currency conversion (including crypto)

### Technical Requirements Discussion

- Chargeback handling for previously reconciled transactions
  - Requires enrichment of original transaction files
  - Dependent reconciliation strategies
- New payment processor integration support
