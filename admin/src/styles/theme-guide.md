# Theme usage guide

Cloviana's app uses [theme.css](theme.css), imported by [globals.css](globals.css). The theme contains the standard light, spacing, typography, shape and motion tokens from `@atlaskit/tokens` **20.7.0**.

| File                                   | Purpose                                                                                                              |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| [theme.css](theme.css)                 | Editable token values, compatibility aliases, typography/border utilities, popup motion and reduced-motion handling. |
| [theme.tokens.json](theme.tokens.json) | All 619 original token names, CSS variables, descriptions, value snapshots, aliases and lifecycle metadata.          |
| This guide                             | Project mappings, migration coverage and the complete original usage descriptions.                                   |

Source: [Atlassian's token catalogue](https://atlassian.design/components/tokens/all-tokens), extracted from [the archived package](../../atlaskit-tokens-20.7.0.tgz). Descriptions remain pinned to package 20.7.0. Dark, legacy and feature-specific themes are outside this reference.

## Choosing tokens

Choose tokens by the element's purpose. Equal values can have different meanings and can diverge when customised. Read the per-token description before applying a new role. Use corresponding hovered and pressed states; preserve selected colours when a selected element is hovered or pressed. Keyboard focus uses `color.border.focused` with `border.width.focused`, independently of selection and validation borders.

Token status and replacement information are preserved below and in the JSON. Experimental tokens are identified explicitly. App spacing and dimensions use standard Tailwind numeric utilities. The original spacing tokens remain documented as a reference; semantic `space.gap.*` and `space.inset.*` tokens in this package are experimental.

## Surfaces, controls and feedback

| UI role                                                        | Tokens / utilities                                                                                                    |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Primary page canvas and static cards                           | `elevation.surface` / `bg-surface`. Static bordered cards use `border-line` or a ring sized with `--ds-border-width`. |
| Sidebar, secondary grouping and passive container backgrounds  | `elevation.surface.sunken` / `bg-surface-sunken`.                                                                     |
| Sheets, menus, comboboxes, mobile navigation and dragged cards | `elevation.surface.overlay` + `elevation.shadow.overlay` / `bg-surface-overlay shadow-overlay`.                       |
| Movable raised cards                                           | `elevation.surface.raised` + `elevation.shadow.raised` / `bg-surface-raised shadow-raised`.                           |
| Neutral filled action                                          | `background-neutral`, `background-neutral-hovered`, `background-neutral-pressed`.                                     |
| Quiet or outline action                                        | `background-neutral-subtle` and its hovered/pressed states; structural outline colour `border-default`.               |
| Primary action                                                 | `background-brand-bold` and its states, paired with `text-inverse`.                                                   |
| Destructive action                                             | `background-danger-subtler` with `text-danger`, or `background-danger-bold` with inverse text.                        |
| Selected navigation or menu item                               | `background-selected` and its states, `text-selected`, and `icon-selected` for its icon.                              |
| Disabled control                                               | `background-disabled`, `border-disabled`, `text-disabled` and `icon-disabled`.                                        |
| Form input / textarea / picker                                 | `background-input` and its states, `border-input`, `text-default`, and `text-subtlest` placeholders.                  |
| Skeleton                                                       | `skeleton` / `bg-skeleton`.                                                                                           |
| Nonsemantic tags and avatar placeholders                       | Matching `background-accent-gray-*` and text roles.                                                                   |
| Loading illustration                                           | `opacity.loading` / `opacity-(--ds-opacity-loading)`.                                                                 |
| Media hover and selection overlays                             | `interaction.hovered` and `blanket.selected`; selected boundaries use `border.selected` with `border.width.selected`. |
| Product status dots                                            | `icon.warning`, `icon.information`, `icon.success`, `icon.danger`.                                                    |
| Toasts                                                         | Overlay shadow, semantic feedback background/border/text/icon tokens, and token typography.                           |

Use `text-text-default` for primary content, `text-text-subtle` for supporting descriptions and `text-text-subtlest` for metadata, breadcrumbs and helper text. Links use `text-link-default` and `active:text-link-pressed`. Inverse content is paired with the corresponding bold background. Current-colour glyphs inherit the semantic foreground of their control; independent status and navigation icons use icon-role tokens.

The theme uses shared default, hovered and pressed input colours across every surface. Surface-dependent input overrides and `data-surface` markers have been removed.

## Typography

Composite text utilities apply the full CSS `font` shorthand, including family, weight, size and line height. The class-merging helper treats them as typography, preserving separate colour utilities. Explicit font-weight classes retain their normal override behaviour.

| Context                                            | Utility / token                                                                         |
| -------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Page title, including login/signup titles          | `text-heading-large` / `font.heading.large`.                                            |
| Sheet or dialog title                              | `text-heading-medium` / `font.heading.medium`.                                          |
| Section, card or empty-state heading               | `text-heading-small` / `font.heading.small`.                                            |
| Compact card heading                               | `text-heading-xsmall` / `font.heading.xsmall`.                                          |
| Default component content                          | `text-body` / `font.body`.                                                              |
| Labels, buttons and text beside icons              | `text-body font-medium` / `font.body` + `font.weight.medium`.                           |
| Caption, compact badge, helper message or metadata | `text-body-small` / `font.body.small`, used for secondary content.                      |
| Large body text and mobile native input text       | `text-body-large` / `font.body.large`. Mobile native inputs retain the 16px token size. |
| Code                                               | `text-code` / `font.code`.                                                              |
| Metrics                                            | `text-metric-small`, `text-metric-medium`, `text-metric-large`.                         |

`Heading` variants map `page` to large, `dialog` to medium, `section` to small and `compact` to xsmall. `Text` variants combine body tokens with the appropriate foreground. Rich-text headings and code consume the same tokens as the rest of the app.

```tsx
<Heading as="h1" variant="page">Products</Heading>
<p className="text-body text-text-subtle">Supporting description</p>
```

```css
.dialog-title {
  font: var(--ds-font-heading-medium);
  color: var(--ds-text);
}
```

The archive supplies font stacks, not font binaries. Named Atlassian fonts use their supplied system fallbacks until font files are loaded. The app no longer loads the unused Inter font through its root layout. Composite shorthand tokens contain literal stacks; update those shorthands too if changing a family. The `font-inter` alias is retained only for compatibility, with no current component consumers.

## Spacing, dimensions, radii and borders

Use standard Tailwind spacing and dimension utilities: `gap-2` (0.5rem), `p-4` (1rem), `h-8` (2rem), and `size-4` (1rem). These preserve the previous Atlassian scale values while allowing `cn()` / `tailwind-merge` to resolve overrides without custom spacing configuration. CSS calculations use Tailwind's `--spacing()` function. Original `--ds-space-*` variables and their compatibility aliases remain available as a reference; app components no longer consume them. Radius utilities such as `rounded-md` continue to use the theme's radius values.

Control dimensions and icon sizes use the standard Tailwind scale. Compact/default controls use the available 24px/32px tokens; large controls use 40px. Spacing values that fell between available source tokens were aligned to the scale. Image ratios, responsive content widths, sidebar widths, popup positioning offsets and grid row/column calculations are layout constraints. Image resource `sizes` hints and intrinsic artwork dimensions also retain their original purpose. Tailwind spacing and token border widths are referenced inside layout calculations when they affect the result.

| Element                                               | Radius / width utility                                                  |
| ----------------------------------------------------- | ----------------------------------------------------------------------- |
| Checkbox or fine detail                               | `rounded-xs` / `radius.xsmall`.                                         |
| Tag, compact supporting element or tooltip            | `rounded-sm` / `radius.small`.                                          |
| Button, input, toggle, select item or navigation item | `rounded-md` / `radius.medium`.                                         |
| Static card, menu or image container                  | `rounded-lg` / `radius.large`.                                          |
| Large sheet or page container                         | `rounded-xl` / `radius.xlarge`.                                         |
| Circular avatar or circular indicator                 | `rounded-full` / `radius.full`.                                         |
| Structural border                                     | `border-line`, `border-t-line`, `border-b-line`, etc. / `border.width`. |
| Selected underline or boundary                        | `var(--ds-border-width-selected)`.                                      |
| Keyboard focus ring                                   | `ring-(length:--ds-border-width-focused) ring-border-focused`.          |

```tsx
<div className="border-line border-border-default flex gap-2 rounded-lg p-4">
  <Button variant="secondary">Continue</Button>
</div>
```

## Motion and third-party UI

Shared transitions use `duration.short` and `easing.out.practical`. Popup enter/exit utilities select the matching `motion.popup.*` token for the side; both Base UI and Radix state attributes are mapped explicitly. Sheets and backdrops use the panel/blanket duration and easing roles. Sidebar height transitions use medium duration with practical enter/exit easing.

Media reorder transitions read CSS duration/easing variables, and drop animations read the theme on drag start. Reduced-motion preferences disable those animations. Continuous spinner and skeleton cycles derive their duration from `duration.xxlong`; linear spinner rotation is intentionally continuous. The existing browser autofill suppression delay is a browser workaround, separate from UI motion; its fill and text colours use theme tokens.

Sonner receives token colours, radius, typography, spacing and focus styles. React Data Grid receives token text, default/hover/selected surfaces, borders, focus width, typography and cell padding. Its column widths, row heights, virtualization and editor behaviour remain layout/interaction concerns.

## Cloviana compatibility choices

These are project decisions, separate from the original Atlassian descriptions.

| Area                                | Mapping                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Brand palette                       | Primary actions use Apollo-style yellow `#EBF213`, hovered `#DFE610`, pressed `#D0D70D`, with **dark** `text-default` text (white fails contrast on yellow). Yellow is not legible as text, icon or border on white, so brand text, icons, borders, selected-bold fills and charts use charcoal `oklch(27% 0 0)`. Links, focus indicators and information colours remain blue. |
| Selection palette                   | Soft selection backgrounds use opaque neutral greys based on the original theme's fills on white, avoiding repeated alpha layering in grids. Selected text, icons and indicators use charcoal; selection blankets use a neutral tint.                                                                                                                                          |
| Inset page                          | Uses the primary surface. Optional inset spacing and radius remain; the static page does not use a movable-card elevation.                                                                                                                                                                                                                                                     |
| Floating sidebar and mobile sidebar | Use overlay surfaces; the floating sidebar uses the overlay shadow.                                                                                                                                                                                                                                                                                                            |
| Selected-subtler alias              | `--background-selected-subtler` resolves to the opaque official selected background.                                                                                                                                                                                                                                                                                           |
| Structural divider alias            | `--border-divider` resolves to `--ds-border`.                                                                                                                                                                                                                                                                                                                                  |
| Input/control border aliases        | `--border-control` resolves to `--ds-border-input`; `--border-input-hovered` resolves to `--ds-border-bold`.                                                                                                                                                                                                                                                                   |
| Tooltip fill                        | `--background-tooltip` resolves to `--ds-background-neutral-bold`, paired with inverse text.                                                                                                                                                                                                                                                                                   |

## Maintaining the reference

Edit values in `theme.css`; update project choices here when their intended use changes. JSON values and alias lists are snapshots, so refresh them when editing or upgrading the theme. Keep original package descriptions separate from Cloviana notes. The JSON includes original names, CSS variables, source/current snapshots, introduction versions, lifecycle status, static aliases and original `attributes` (including replacements and suggestions). Dynamic popup direction aliases are documented in the motion section rather than assigned to one token in the JSON.
